# Cap กับ hCaptcha

hCaptcha คือคู่แข่งของ reCAPTCHA ที่วางตัวเป็นฝ่ายรักษาความเป็นส่วนตัว แต่ยังใช้ปริศนาเป็นหลัก แพ็กเกจฟรีเสิร์ฟปริศนารูปภาพอย่างหนักมือ ส่วนแพ็กเกจ Pro แบบเสียเงิน (99 ดอลลาร์ต่อเดือนเมื่อจ่ายรายปี, 139 ดอลลาร์ต่อเดือนเมื่อจ่ายรายเดือน, 100,000 การประเมิน) จะปลดล็อกโหมดที่แทบไม่รบกวนผู้ใช้พร้อมระบบวิเคราะห์ข้อมูล ในบรรดา CAPTCHA รายใหญ่ นี่คือเจ้าที่ดันปริศนาแบบมองเห็นได้หนักที่สุดในแพ็กเกจฟรี

## สรุปสั้น ๆ

ถ้าคุณใช้ hCaptcha เพราะอยากหนีจาก Google เป็นหลัก Cap คือก้าวที่ง่ายกว่า คุณไม่ได้แลก Google กับบุคคลที่สามรายอื่น แต่คือเลิกมีบุคคลที่สามไปเลย และคุณก็เลิกเก็บ "ภาษีปริศนา" จากผู้ใช้ทุกครั้งที่ส่งฟอร์ม

## hCaptcha เหมาะเมื่อไร

- คุณต้องการฟีดข่าวกรองภัยคุกคามและการให้คะแนนความเสี่ยงของ hCaptcha Enterprise ในระดับใหญ่โดยเฉพาะ และมีงบพร้อม
- คุณผูกกับมันลึกแล้ว และต้นทุนการย้ายมากกว่าประโยชน์ที่ได้
- โปรแกรมกำกับดูแลของคุณกำหนดให้ต้องมีขั้นตอนยืนยันความเป็นมนุษย์ด้วยปริศนาที่มองเห็นได้ สำหรับการกระทำที่อยู่ใต้กฎระเบียบ

## Cap เป็นตัวเลือกที่ดีกว่าเมื่อไร

- **ไม่มีปริศนารูปภาพ** อัตราการเลิกทำปริศนาของ hCaptcha อยู่ที่ **5% ถึง 15%** ขึ้นกับความยาก นั่นคือยอดแปลงเป็นลูกค้าที่คุณเสียไปจริง ๆ ทั้งการสมัคร การชำระเงิน และฟอร์มติดต่อ ส่วน Cap ไม่เคยแสดงปริศนาเลย (โหมดไม่รบกวนของ hCaptcha Pro ช่วยลดเรื่องนี้ได้ แต่ต้องจ่ายเงิน)
- **ขนาดบันเดิล** ไคลเอนต์ของ hCaptcha หนักกว่า 600 KB ส่วน Cap ราว 20 KB หรือเล็กกว่าราว 30 เท่า
- **ไม่มีโควตาหรือค่าใช้เกิน** hCaptcha Pro เริ่มที่ 99 ดอลลาร์ต่อเดือนสำหรับ 100,000 การประเมิน แล้วคิดเพิ่ม 0.99 ดอลลาร์ต่อ 1,000 ครั้ง ส่วน Cap ฟรีทุกปริมาณ รันบน VPS ราคา $5 และไม่มีค่าธรรมเนียมต่อคำขอ
- **โฮสต์เองได้** ไม่ต้องพึ่งบุคคลที่สาม Cap ไม่โหลดอะไรจาก `hcaptcha.com` เลย
- **ไม่เก็บลายนิ้วมือ** hCaptcha พึ่งลายนิ้วมือเบราว์เซอร์และสัญญาณเชิงพฤติกรรม ซึ่งกระทบผู้ใช้เบราว์เซอร์ที่เน้นความเป็นส่วนตัว ส่วน proof-of-work ของ Cap ทำงานเหมือนกันไม่ว่าจะเบราว์เซอร์ไหน
- **โอเพนซอร์ส** Apache 2.0 ตรวจสอบได้ รันบนระบบที่ตัดขาดจากเครือข่ายได้ fork ได้

## สิ่งที่คล้ายกัน

ทั้งคู่รันชั้น instrumentation หรือเชิงพฤติกรรมเพิ่มจาก challenge ที่มองเห็นได้ ทั้งคู่มีโหมดล่องหน และทั้งคู่ใช้งานได้กับรูปแบบการส่งฟอร์มมาตรฐาน

## การย้ายระบบ

`/siteverify` ของ Cap มีรูปแบบ API เข้ากันได้กับของ hCaptcha การแก้ฝั่งแบ็กเอนด์ส่วนใหญ่จึงเป็นแค่เปลี่ยน URL ส่วนฝั่งไคลเอนต์ให้แทนที่ `<div class="h-captcha">` และ `https://js.hcaptcha.com/1/api.js` ด้วย `<cap-widget>` ของ Cap ดู[คู่มือเริ่มต้นใช้งาน](../index.md)

ถ้าอยากย้ายแบบค่อยเป็นค่อยไป ให้ใช้ Cap กับฟอร์มใหม่ก่อน คงไว้ hCaptcha บนฟอร์มเดิม แล้วดูส่วนต่างของอัตราการเปลี่ยนเป็นลูกค้า
